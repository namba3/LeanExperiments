# LeanExperiments

[日本語](README.md) | [English](README.en.md)

A Lean 4 project for implementing algorithms and practicing by checking their behavior and properties. Algorithm implementations, command-line interfaces, and verification specifications and proofs are kept in separate areas.

See the [documentation index](docs/README.md) for the full document list.

## Requirements

- Lean 4.35.0 (managed by `elan` and pinned in `lean-toolchain`)
- Lake (included with Lean)

## Build

Run this from the project root:

```sh
lake build
```

This builds the library and all command-line programs. Run an individual CLI with `lake exe <name>`.

## Command-line programs

The factorial, prime factorization, and Fibonacci commands each read one non-negative integer from standard input. All sorting and median commands read zero or more whitespace-separated non-negative integers. Invalid tokens, or multiple values passed to a command that expects one, are reported on standard error and produce exit code 1.

```sh
printf '10\n' | lake exe factorial
# 3628800

printf '360\n' | lake exe prime-factors
# 2 2 2 3 3 5

printf '100\n' | lake exe fibonacci
# 354224848179261915075

printf '9 1 4 2 7 3\n' | lake exe median
# 3.5

printf '9 1 4 2 7\n' | lake exe median
# 4

printf '7 2 5 2 0 9\n' | lake exe heapsort
# 0 2 2 5 7 9

printf '7 2 5 2 0 9\n' | lake exe heapsort-rec
# 0 2 2 5 7 9

printf '7 2 5 2 0 9\n' | lake exe mergesort
# 0 2 2 5 7 9

printf '7 2 5 2 0 9\n' | lake exe mergesort-loop
# 0 2 2 5 7 9

printf '7 2 5 2 0 9\n' | lake exe quicksort
# 0 2 2 5 7 9

printf '7 2 5 2 0 9\n' | lake exe quicksort-loop
# 0 2 2 5 7 9
```

Each sorting algorithm has recursive and loop-based versions. `heapsort`, `mergesort-loop`, and `quicksort-loop` are loop-based; `heapsort-rec`, `mergesort`, and `quicksort` are recursive. The recursive heap sort uses recursive descent, heap construction, and extraction. The loop-based merge sort repeatedly merges adjacent sorted runs. The loop-based quick sort uses an explicit task stack instead of recursive calls.

Both quick sort versions choose the first element as the pivot. This can produce unbalanced partitions for inputs such as already sorted lists, leading to deep recursion in the recursive version or a large task stack in the loop-based version.

Run `lake exe median` to compute a running median. Each input value is placed in a max-heap for the lower half or a min-heap for the upper half. Insertion takes `O(log n)` and reading the median after insertion takes `O(1)`. For an even number of values, the command prints the average of the two middle values; empty input prints `none`.

Fibonacci uses fast doubling, halving the index at each recursive call and therefore using logarithmic recursion depth. Prime factorization uses trial division and returns factors in ascending order with multiplicity.

## Source layout

- `Apps/`: CLI entry points for input, algorithm calls, and output.
- `LeanExperiments/`: reusable algorithms and shared utilities.
- `LeanExperiments/Verification/`: specifications, lemmas, and proofs grouped by algorithm.

Import `LeanExperiments.Algorithms` for the executable algorithms and `LeanExperiments.Verification` for specifications and proofs. The historical `LeanExperiments` import remains as a compatibility umbrella for both.

## Verification

Specifications, lemmas, proofs, and finite regression checks live under `LeanExperiments/Verification/`. Both recursive and loop-based quick sort, merge sort, and heap sort have general correctness proofs for arbitrary inputs. Loop-based quick sort is proved equal to its recursive counterpart using a loop invariant and termination measure, then connected to the shared `Correct` specification. See the [verification catalog](docs/verification.en.md) for proof scope, finite domains, and remaining work.

Almost all code under `LeanExperiments/Verification/` was generated by AI. Lean accepting a proof is separate from whether its specification and verification scope are appropriate, so consult the verification catalog for each proof's scope and remaining work. GitHub Actions builds all Lean targets, checks audit-file reachability and the public Verification API baseline, runs negative audit-tool tests, audits axiom dependencies, and checks CLI input/output. See the [verification catalog](docs/verification.en.md) for scope and comparison limitations.
