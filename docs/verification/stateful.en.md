## CLI input

Source: `LeanExperiments/Verification/CLI/Spec.lean`

### General theorems

For any token list, the multi-value parser agrees with the independent `List.mapM String.toNat?` specification. A single invalid token fails the whole list; on success, every parsed value and its order are preserved. Specification failure is characterized exactly by the presence of an unconvertible token. Whitespace splitting is proved equivalent for arbitrary input: the implementation splits string slices, while the specification splits a character list and removes empty pieces. These results compose into an exact error characterization for the input-string parser: it reports a conversion error iff the independent split contains an invalid token.

The multi-value parser succeeds exactly when every token after whitespace splitting converts to a natural number. Its successful values and their order are fixed by the independent `List.mapM String.toNat?` specification.

The single-value parser has a complete result-classification theorem for arbitrary input directly against the independent character-list splitting and `List.mapM String.toNat?` specification. It succeeds exactly when that specification returns the singleton list containing the value. It also succeeds exactly when the multi-value parser succeeds with one element; failures arise only from conversion failure propagation or an element-count mismatch. The standard-input IO layer calls these verified pure functions.

Sorting CLIs use the shared pure formatter `formatNatList`. General theorems show that appending a value to the array formats as that value alone for an empty array, or as one separating space followed by the value otherwise. Formatting the concatenation of two nonempty arrays equals joining their separate formatted outputs with one space. General agreement between each formatted sorting implementation and the independent MergeSort string is in `Verification/CLI/Sorting.lean`. OS writes and process termination remain outside this pure contract.

The median CLI's numerator and denominator formatter is also a pure function, `formatMedian`, in the shared CLI module. For arbitrary input, formatting the public `medianOf` result equals formatting the independent sorting-based `medianSpec` result. This connects the general algorithm-specification theorem to the value displayed by the CLI.

### Finite checks

Lean computation checks empty and whitespace-only input, space-separated values, integers wider than 64 bits, invalid tokens, and empty, whitespace-only, and multiple-value inputs for the single-value parser.

### Runtime resource boundary

The general parser theorems establish value and error semantics for every finite input string; they do not bound memory or running time. `readNatList` and `readNat` currently read standard input through EOF into one string, then create split tokens and a result array. The original input, tokens, and array can therefore occupy memory at the same time. Memory limits, large-input performance, and recursion depth have not been measured or bounded. Alongside QuickSort's pivot-degeneration cases, whole-input buffering is an operational limitation.

## Running median

Source: `LeanExperiments/Verification/RunningMedian/Spec.lean`

General heap-operation contracts are in `Operations.lean`; the sorted-input median specification, independent of the implementation state, is in `MedianSpec.lean`. The existing `Spec.lean` imports both and remains the compatibility entry point for state invariants, correctness proofs, and finite checks.

### General theorems

#### Local heap-adjustment invariants

- Even with one exceptional edge, any-depth parent-child paths that avoid it preserve endpoint non-preference, assuming irreflexivity and transitivity of non-preference. In the subtree rooted at the exceptional position, every descendant is shown not to be preferred to its root. After swapping the exceptional position with its parent, values below the old exceptional position and every descendant in its sibling subtree are shown not to be preferred to the old parent value moved there. The shared HeapSort specification also proves that sibling subtrees do not intersect. Under an asymmetric preference relation, the swapped edge itself has the correct order; if preference is transitive, the sibling edge has the correct order too. Together these facts prove a general one-swap transition that preserves the exceptional-edge invariant and its subtree bound while moving both up one level. A stopping lemma recovers the full heap-order property when the exception is at the root or its parent comparison stops, and a corollary proves this for `siftUp` runs that stop without swapping. Appending a leaf initializes the same invariant and bound. The loop invariant connects these facts to arbitrary-length `siftUp` and proves heap-order preservation after any number of swaps.

#### Median specification and derived properties

- The independent sorting-based median specification returns `none` exactly for empty arrays. For every nonempty array, the specification is defined; this follows from length preservation by sorting. A general theorem also gives the result for every singleton input: its sole value over denominator 1.
- Whenever the reference median returns a result, its denominator is 1 for odd input lengths and 2 for even input lengths. The public implementation also returns a result for every nonempty input and has the same denominator parity. These general theorems have no bound on input values or length.
- If every input value lies between `lowerBound` and `upperBound`, the public median value also lies in that range. In its numerator/denominator representation, the numerator is bounded by the bounds scaled by the denominator. For even lengths, the denominator is 2. This is a general theorem for arbitrary input lengths and value ranges.
- For odd lengths, the median value is an input element. For even lengths, it is the average of an ordered pair of input elements. These arbitrary-length theorems characterize which input values construct the returned median.
- For odd lengths, the number of inputs below the returned value is at most the middle rank, while the number at or below it exceeds that rank. For even lengths, the two roots used in the average are characterized by the adjacent middle ranks, including duplicate values.
- Adding the same natural number to every input value shifts the public median by that amount. In numerator/denominator form, the numerator increases by `offset * denominator`; the theorem also covers empty input. It follows generally from the mapping law for the independent sorting specification.
- Multiplying every input value by a natural number `factor` multiplies the public median numerator by `factor`. This applies to arbitrary input, including factor zero.
- Combining these laws, mapping every value to `factor * value + offset` preserves the denominator and maps the numerator to `factor * numerator + offset * denominator`. The general theorem includes factor zero and empty input.
- A general theorem proves that the implementation preserves its state invariant after inserting any value into any invariant state. Combining it with the independent median theorem proves that public `medianOf` agrees with the sorting specification for arbitrary input lengths and values.
- Since these results hold for every prefix, the Boolean checker `inputCheck` is also proved to succeed for every input. Finite exhaustive checks remain separate evidence for representative execution regressions.
- The public function returns `none` if and only if the input is empty. This unconditional theorem composes the invariant-conditional result with the arbitrary-length state invariant.

#### Arbitrary-length state construction and insertion

- Processing empty input yields the empty state, which satisfies the logical invariant. This base case and arbitrary one-insertion preservation compose by list induction to establish the invariant for every input sequence.
- For every value `value`, one implementation insertion into the empty state directly establishes the state invariant. This is a concrete instance of the arbitrary one-insertion theorem and requires no enumeration of values.
- Combining this invariant with the general specification-agreement theorem proves that the public function `medianOf #[value]` returns `value` over denominator 1 for every `value`.
- A bounded-length theorem also shows that for arrays of length 0 or 1, the result is either empty or the sole input value. It places no bound on that value.
- The permutation component of the invariant also yields a general theorem that the two heap sizes sum to the input length.
- For every array and value, `ofArray (values.push value) = insert (ofArray values) value`. This exposes the fold's exact recurrence and reduces a full-input invariant proof to preservation by one insertion.

#### Heap operations and rebalancing contracts

- For any priority function, array, and index, upward and downward sifting preserve the array length, and heap insertion increases the element count by one. Upward sifting leaves the array unchanged when it starts at the root or when the initial parent comparison does not request a swap. It also leaves any already ordered heap unchanged when started at an in-bounds index. If the heap is empty or the inserted value does not outrank the final leaf's parent, insertion is exactly a push to the end. For an already ordered heap, this parent comparison is also necessary: the pushed array is ordered if and only if the heap is empty or the new value does not outrank its parent. For the max-heap comparator, the stop condition holds when the inserted value is no greater than its parent; for the min-heap comparator, it holds when the parent is no greater than the inserted value. These conditions preserve the shared `MaxHeap` specification and numerical `MinHeap` specification, respectively. The max-heap condition used by RunningMedian is equivalent to HeapSort's shared `MaxHeap` specification. Inserting into an empty heap yields the singleton array containing the value at its root. After insertion, the root is either an element of the original heap or the newly inserted value. Upward sifting from an in-bounds index and heap insertion preserve the input elements plus the newly inserted value as a permutation. The count of elements satisfying any Boolean predicate increases by one exactly when the inserted value satisfies it. Downward sifting preserves the element permutation, and each step leaves positions outside the current index and selected candidate unchanged. In particular, the processed array prefix before the current index remains unchanged. On an already ordered heap, it leaves the array unchanged when started at any in-bounds index, for any priority function. At a position with no children, one step stops and preserves the array and index for any priority function. A local stopping condition also suffices to make the current position the downward-sift candidate: the array need not be a heap, only the existing children must not outrank that position. The candidate picker always returns the current index or one of its two child indices; the continuing-step path proof reuses this general fact. For the min-heap comparator, each downward-sift step selects an in-bounds index whose value is no greater than the current position or either existing child. After the step, the processed position is ordered with each existing child. When the step continues, the edge from the old position to the next processing position is also ordered after the swap. For a first descent from a root whose lower edges are ordered, a separate lemma establishes that the new root is no greater than the next processing position and its child candidates, initializing the path condition. A separate transition lemma shows that an earlier processed value remains no greater than the next processing value when it is no greater than the current node and either child candidate. A general transition contract combines index progress, the in-bounds condition, decrease of the stopping measure, this path edge, and preservation of the processed prefix. The `MinHeapExcept` invariant allows only the current row to violate heap order. The first root exchange initializes this exception and the path bounds; a continuing exchange moves the exception to the selected child and preserves the parent-to-current and parent-to-child bounds needed for the next path step. When a step stops, its local row ordering recovers the full min-heap property. A combined one-step contract packages length preservation, element permutation, and the local ordering. Reevaluating that same position stops without changing the array or index. The `MinHeapSiftInvariant` packages the initialization, transition, and stopping conditions, and a theorem proves its preservation by one step. A VCGen invariant with an explicit loop-exit flag proves the general theorem: if all rows below the root are ordered, the complete `siftDown` result is a min-heap. `popHeap` returns `none` exactly for an empty array. On success, it reduces the array length by one and retains a permutation of the input with its root removed, for any priority function. The removed root and residual together preserve the count of every Boolean classification from the input. For any reflexive and transitive priority relation, an ordered heap's root is preferred to every element, so the maximum and minimum heap roots are respectively the greatest and least input values. Max-heap sift-down agrees with the verified HeapSort descent for arbitrary inputs; if all parent-child edges below the root are ordered, the descent restores the heap property across the whole array. Max-heap root removal also agrees with the verified HeapSort `popMax` and satisfies its maximum, residual-heap, and element-preservation contract. A stopped downward-sift step preserves the array and index; a continuing step moves to an in-bounds child and preserves the elements. The full loop preserves both array length and the element permutation, using `heap.size - index + 1` as a measure that also decreases on the final stopping iteration.
- For any priority function, a closed interval containing every original heap element and the inserted value also contains every element after insertion. A separate theorem states the upper-bound case.
- For any priority function and array, the heap checker is equivalent to the condition that no existing child outranks its parent. Specializing it to the min-heap comparator gives an exact characterization by the numerical `MinHeap` specification: each existing child is at least its parent. The numerical specification proves that every ancestor is no greater than any descendant in its subtree; the root bound for every array element follows as a special case. A combined contract for successful `popHeap` also proves that it returns the input minimum, leaves a permutation of the non-root elements, and reduces the length by one. A general lemma proves that replacing a min-heap root with any value preserves every parent-child edge below the root. Removing the root also preserves the heap order of the remaining array; these results combine to show that replacing the popped root with the last value preserves all edges below the root, isolating the remaining repair to the root subtree. Combining the below-root preservation result with the general `siftDown` theorem proves that `popHeap` preserves the min-heap property of the residual. An unconditional extraction contract now combines this with the existing minimum, permutation, and length results. If the priority relation is transitive, the root is at least as preferred as every element.

#### Median results and state checker

- The size invariant establishes that an odd-sized state returns the lower heap root and an even-sized state returns the average of both roots. It also guarantees a result for every nonempty state. The proofs establish that the roots come from the input and that the lower root is no greater than the upper root.
- Bounds on input values yield corresponding bounds on the median. Separate results characterize the boundary values for odd and even input sizes.
- The state checker is equivalent to a condition that partitions the input elements, uses the shared `MaxHeap` and numerical `MinHeap` specifications, orders the two heaps against each other, and balances their sizes. Given the heap-order properties, the all-pairs boundary condition is equivalent to comparing only the roots. Separate general lemmas also show that inserting into either heap preserves the cross-heap boundary whenever the new value lies on the correct side; these use the insertion permutation contract. The implementation routing cases establish that condition from the lower root: values greater than it go to the upper heap, and values no greater than it go to the lower heap. A combined theorem collects both branch results. Under the invariant, an empty lower heap implies an empty upper heap, so a general theorem also covers boundary preservation across the complete routing branch, including the empty case. For the pre-rebalancing routing step, the theorem follows the implementation's branches: an empty lower heap receives the value, while a nonempty lower heap routes by comparing against its root. The selected heap grows by one and the input partition is preserved. An abstract single transfer that pops a root and inserts it into the other heap preserves the permutation of the concatenated heaps and their combined size in both directions. This transfer contract does not establish preservation of either heap-order property. This independent specification is also proved equivalent to the logical invariant stated with the generic `HeapOrdered` predicate. A successful state check directly proves that the nonempty lower root is no greater than the nonempty upper root. It also implies the lower heap maximum-extraction contract and the upper heap minimum, residual-permutation, and length contracts. Under the invariant, the number of input elements satisfying any Boolean predicate is exactly distributed across the two heaps, including exact occurrence counts for each value. Sorting both heaps separately and concatenating them, as well as converting that concatenation to an array, exactly matches the merge-sort result for the input in the corresponding representation. The median computed from the heap roots therefore matches the sorting-based specification. A general theorem connects this result to the public `medianOf` function whenever its final state satisfies the invariant.

#### Insertion and rebalancing contracts

- For any invariant state, insertion of any value preserves the complete state invariant. The proof follows both routing branches and composes heap-order and boundary preservation, input partition preservation, and size balancing after rebalancing. A fold induction then proves the invariant for `ofArray` on arbitrary input arrays.
- From a state of sizes 1 and 2, the upper rebalancing loop is proved to move the minimum to the lower heap and stop, with no assumptions on the values. This concrete transition is covered by the arbitrary-size rebalancing contracts.
- The final heap arrays after inserting a value greater than the lower root into a one-element-per-heap state are characterized by a general equation split on the value's relation to the upper root. This equation proves both the complete output invariant and acceptance by the independent state checker.
- For any state whose heaps partition an input, one insertion preserves the exact count of every Boolean classification: the new count is the input count plus one precisely when the inserted value satisfies the predicate. This general contract includes duplicate values.
- For both max-priority and min-priority `popHeap`, an arbitrary two-element array yields its root and the remaining singleton. The resulting transfer into an empty opposite heap is also characterized in both directions.
- If the pre-insertion heaps partition an input, their combined size after insertion is exactly the input length plus one.
- The two rebalancing loops preserve the count of every Boolean classification, derived from their element-permutation contract.
- For every input length, the final state returned by `ofArray` distributes the exact count of every Boolean classification across its two heaps. The general state-invariant theorem also establishes the full heap-order, boundary, partition, and balance conditions.

#### Composition and derived state laws

- Replacing the input array with any permutation of the same elements preserves both the logical invariant and the Boolean check result, for arbitrary arrays and states. A separate unconditional theorem proves that permuting any input leaves the public median unchanged.
- The lower and upper heap sizes equal `(input.size + 1) / 2` and `input.size / 2`, respectively. The whole-input check examines every prefix; its result yields both the invariant and median agreement at every prefix.
- The invariant proves both directions of the parity relation: even input length is equivalent to equal heap sizes, and odd length is equivalent to one extra lower element.
- The all-prefix Boolean check `inputCheck` succeeds if and only if every prefix satisfies the state invariant, and it is proved to succeed for every input. The invariant yields agreement between public `medianOf` and the sorting-based specification. A state-composition law covers concatenated input arrays; arbitrary permutation-related inputs have equal medians, and a separate theorem needs only the final-state invariant.

- If the original heap is ordered, success of `heapCheck` after appending is equivalent to the new leaf stopping at its parent. This characterizes a plain append and does not prove heap-order preservation after general `siftUp`.

### General proof coverage

#### Downward sifting and root extraction

Max-heap and min-heap descent, both root-removal contracts, and the generic priority theorem for extracting an ordered heap's root are proved. In particular, if all edges below the root of a min-heap are ordered, `siftDown` restores the full min-heap property; `popHeap` returns the minimum and preserves the min-heap property of the residual.

#### `siftUp` and insertion

A general locality theorem also proves that `siftUp` leaves every valid position after its starting index unchanged, for any array and priority function. If the starting index is in bounds, every valid position outside its ancestor path is unchanged as well. The condition for a push to preserve an already ordered heap is characterized exactly by the new leaf's parent comparison. For any array and starting index, a general theorem proves that `siftUp` under any priority function leaves the root unchanged when the starting value is not preferred to the root. The insertion corollary applies under the same condition; specialized results cover values no greater than the root for max-priority heaps and values no less than the root for min-priority heaps. For an arbitrary array, general theorems prove that `siftUp` swaps either depth-one child with the root and stops whenever that child is preferred. Theorems prove two upward swaps from index 3, 4, 5, or 6 when the value there is preferred to both its parent and the root. For indices 7 and 8 at depth three, general equations for any array and priority function prove stop, one-, two-, and three-swap paths to the stopping point, given the corresponding path comparisons. A general equation also covers index 9: when the value is preferred to its parent at index 4 and ancestor at index 1, but not to the root at index 0, `siftUp` swaps through indices 4 and 1 and stops. General theorems prove arbitrary-value insertion order preservation for seven- and eight-element max-heaps and min-heaps, covering stop, one-, two-, and three-swap cases; array contracts are provided for size eight. These fixed-depth equations are complemented by a general arbitrary-depth result: an initialized exception-edge and subtree-bound invariant, together with an asymmetric and transitive preference relation, proves that `siftUp` restores heap order after any number of swaps. Consequently, insertion preserves max-heap and min-heap order for heaps of any size. General theorems also prove that inserting into any six-element max-heap or min-heap preserves its heap order across the stop, one-swap, and two-swap branches. The earlier fixed-length running-median insertion proofs, including lengths 11 through 16, remain useful as focused regression evidence. The fully general proof now combines routing, root transfer, rebalancing, permutation, and size contracts; list-fold induction yields the invariant for `ofArray`, and the public median agrees with the independent sorting specification for every input length and value. Finite computation checks remain separate bounded regression evidence.

### Finite checks

- Every prefix is checked for all 87,381 inputs of length 0–8 over values 0–3 and all 97,656 inputs of length 0–7 over values 0, 1, 2, `2³²`, and `2⁶⁴−1`. The general invariant theorem then yields median agreement for each input.
- Checks include monotone, all-equal, and alternating sequences of length 64, plus alternating 64-bit boundary values.
- The empty-input result of `medianOf` is derived from the general invariant and specification-agreement theorems for the empty state.
- The sorting-based median specification has a general two-element theorem: for arbitrary values, including duplicates, it returns their sum over 2. The implementation has the corresponding two-element state invariant and all-prefix checker theorem. These fixed-size results remain useful special cases of the arbitrary-length proofs.
- For any three values, the post-insertion state invariant and Boolean checks for all four prefixes are proved generally. Insertion preservation and checker success are proved for any invariant state over an input of length at most four. Composing these results proves the `ofArray` invariant, all prefix checks, and agreement with the independent sorting specification for every array of size at most five.
- For insertion into any invariant state whose input has at most two elements, a general theorem derives the 1+1 heap shape at length two and reduces to the two singleton-heap branches. It establishes the invariant after insertion, checker success, and median-spec agreement for arbitrary values. The theorem applies to any invariant state, not only one produced by `ofArray`.
- The fixed-size insertion proofs for input lengths three through sixteen record concrete branches used while developing the general proof. The arbitrary-length insertion theorem now composes routing, heap-order and boundary preservation, element partition, and rebalancing size contracts for every invariant state. Fold induction establishes the `ofArray` invariant and all-prefix checker success without relying on the fixed-size cases.
- The size contracts for the rebalance loops apply to arbitrary arrays. A general loop invariant tracks the exceptional edge and subtree bound across every upward swap, then restores full heap order when `siftUp` stops or reaches the root. This proves insertion-order preservation for max-heaps and min-heaps of any size. General lemmas prove that transferring either heap root preserves both heap orders and the cross-heap boundary for arbitrary heap lengths. When the routed heaps differ in size by at most two on the lower side and one on the upper side, the complete rebalancing step preserves both orders and the boundary. The arbitrary-length insertion theorem derives that size range from routing and composes it with the partition and balance contracts, closing the complete state invariant.
- The specification already propagates a transitive priority relation along any parent-child path. In max-heaps this bounds every descendant by its ancestor; in min-heaps every ancestor is bounded by its descendants. These bounds alone do not establish that heap order survives swaps; a separate arbitrary-depth `siftUp` invariant and preservation theorem now provide that proof.
- The four-element and five-element insertion proofs are now exposed through max-heap and min-heap lemmas for any array of the corresponding size. Callers can reuse these contracts without first fixing names for every array element. They support both insertion branches from any invariant state of length nine and ten. The complete arbitrary-length state theorem now follows by composing the generic insertion and fold contracts.
- Every prefix is checked for ascending, descending, and alternating boundary-value sequences at lengths 63, 64, 65, 127, 128, 129, 255, 256, 257, 511, 512, and 513.
- For these finite domains, the invariant and median-agreement propositions can be extracted for each prefix.
