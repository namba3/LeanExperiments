# CLI と逐次処理の検証

## CLI入力

対象: `LeanExperiments/Verification/CLI/Spec.lean`

### 一般証明

複数値パーサーは任意のトークン列で、各文字列に `String.toNat?` を適用する独立仕様 `List.mapM` と一致します。不正トークンが1つでもあれば列全体が失敗し、成功時は値と順序をすべて保ちます。さらに仕様の失敗は、変換できないトークンが列中に存在することと同値です。空白分割も、実装の文字列スライス分割と、仕様側の文字リスト分割・空部分列除去が任意の入力で一致することを証明しています。この結果を合成し、入力文字列のパーサーが変換エラーになることと、独立分割後に不正トークンがあることの同値性も示します。

複数値パーサーが成功することも、空白分割後の全トークンが自然数へ変換可能であることと同値です。成功結果の値と並び順は `List.mapM String.toNat?` の独立仕様で定まります。

単一値パーサーについても、文字リスト上の分割と `List.mapM String.toNat?` からなる独立仕様を直接使い、任意入力での完全な結果分類を証明しています。成功することは、独立仕様がその値1つだけを返すことと同値です。複数値パーサーが成功して1要素を返すこととの同値性、および失敗理由が変換失敗の伝播か要素数不一致に限られることも示しています。標準入力の IO 層は検証対象の純粋関数を呼び出します。

ソートCLIが使う数列の出力整形は共通純粋関数 `formatNatList` に切り出しました。末尾へ値を追加したとき、空配列なら値だけを、そうでなければ区切り空白1つと値を追加します。二つの非空配列を連結した整形結果も、個別の整形結果を空白1つで結んだものと一致します。これらは任意配列・値について証明しています。各ソート実装を整形した純粋文字列が独立なMergeSortの文字列と一致する一般定理は `Verification/CLI/Sorting.lean` にあります。OSへの書き込みやプロセス終了を含む IO 動作そのものは、この純粋仕様の対象外です。

中央値CLIの分子・分母の表示も純粋関数 `formatMedian` として共通CLIモジュールへ移しました。`medianOf` が返す値を整形した文字列は、独立なソート基準 `medianSpec` の値を整形した文字列と任意入力で一致します。これにより、中央値アルゴリズムの一般仕様一致をCLI表示値まで接続しています。

### 有限確認

空入力、空白のみ、空白区切りの複数値、64 bit を超える整数、不正トークン、単一値入力の空・空白のみ・複数値を Lean の計算で確認します。

### 実行時資源の境界

純粋パーサーの一般定理は任意の有限文字列に対する値・エラーの意味を確認しますが、メモリ量や処理時間は保証しません。現在の `readNatList` と `readNat` は標準入力を EOF まで文字列として読み、分割後のトークン列と結果配列も作ります。入力全体、トークン、配列が同時にメモリを使うため、大入力のメモリ上限・性能・再帰深度は測定・制約されていません。QuickSort の pivot 退化に加え、CLI 入力全体の読み込みも運用上の残課題です。

## 逐次中央値

対象: `LeanExperiments/Verification/RunningMedian/Spec.lean`

操作ごとの一般契約は `Operations.lean`、実装状態から独立したソート基準の中央値仕様は `MedianSpec.lean` に分離しています。既存の `Spec.lean` は両モジュールを読み込み、後続の状態不変条件・正当性証明・有限確認をまとめる互換入口です。

### 一般証明

#### ヒープ調整の局所不変条件

- 例外辺を1本だけ許すヒープ順序でも、その辺を通らない任意深さの親子経路なら、自己非優先と非優先関係の推移性から端点間の非優先関係を導けます。例外位置を根とする部分木では全ての子孫が根の値を優先しません。また、例外位置と親を交換した後も、旧例外位置の下の値がそこへ移動した旧親の値を優先しないこと、兄弟部分木の任意の子孫が旧親値を優先しないこと、非対称な優先関係では交換した辺が正しい向きになること、優先関係が推移的なら兄弟側の辺も正しい向きになることを示しました。さらに例外辺の兄弟部分木が例外部分木と交わらないことを HeapSort 共通仕様で示しました。これらから、交換後に新しい例外位置となる親と、値が下がった旧例外位置の双方で子方向の辺が順序を保ち、例外辺とその部分木上限を親へ一段移す一般交換定理を証明しました。例外位置が根、またはその親との比較が停止条件を満たす場合には、例外辺仕様から全ヒープ順序を復元する補題を追加し、`siftUp` が交換せず停止する場合に全ヒープ順序が成立することまで導きます。末尾追加時には新しい葉が持つ子孫部分木が空であることを使い、部分木上限を含む初期不変条件を示します。さらにこの不変条件を `siftUp` のループ不変条件として使い、任意回の交換後に全ヒープ順序が復元されることを証明しました。

#### 中央値仕様と派生性質

- 独立したソート基準の中央値仕様は、空配列の場合に限り `none` になります。任意の非空配列では中央値の結果が定義されることを、整列結果の長さ保存から証明しています。任意の1要素入力では、その唯一の値を分母1で返すことも一般証明しています。
- 参照中央値が結果を返す場合、入力長が奇数なら分母は1、偶数なら分母は2です。さらに実装の公開関数は任意の非空入力で結果が定義され、同じ分母偶奇を満たします。いずれも入力値や長さに上限を置かない一般定理です。
- 入力の全要素が下限 `lowerBound` 以上かつ上限 `upperBound` 以下なら、公開中央値の値もその範囲内です。分子・分母表現では、分子が分母倍した上下限の間にあると示します。偶数長では分母が2になります。この契約も任意の入力長と値域に対する一般定理です。
- 奇数長では中央値の値が入力に含まれ、偶数長では入力に含まれる順序付き二値の平均になります。値域の補題に加えて、返却値がどの入力要素から構成されるかを任意長で特定します。
- 奇数長では、返却値未満の入力要素数が中央順位以下で、返却値以下の要素数が中央順位を超えることを示します。偶数長では、平均を作る二つの根が隣接する中央順位を占めることを重複値込みで特徴付けます。
- 全入力値へ同じ自然数を加えると、公開中央値も同じ分だけ平行移動します。分子・分母表現では、分子に「加算量×分母」を足す式になり、空入力にも適用できます。この性質は独立ソート仕様の写像則を介した一般証明です。
- 全入力値を自然数 `factor` 倍すると、公開中央値の分子も `factor` 倍になります。係数0も含めて任意の入力に適用できます。
- 二つの変換則を合成し、全要素を `factor * value + offset` に写した場合の中央値も、分母を保ったまま分子を `factor * numerator + offset * denominator` に写すと示しています。これは係数0と空入力も含む一般定理です。
- 実装が任意入力で状態不変条件を保つ一般定理を証明しました。これと不変条件から中央値仕様への一般定理を合成し、公開関数 `medianOf` が独立したソート基準の中央値と任意長・任意値で一致します。
- 各接頭辞について同じ不変条件と中央値一致が成り立つため、Boolean 検査器 `inputCheck` が任意入力で成功することも一般定理として導けます。有限網羅確認は代表的な実行回帰を調べる証拠として別に残しています。
- 公開関数 `medianOf` が `none` を返すことと入力が空であることは同値です。不変条件付きの補題を任意長の状態不変条件と合成した無条件定理です。

#### 任意長の状態構築と挿入

- 空入力を逐次処理した結果は空状態であり、その空状態は論理的不変条件を満たします。この基底ケースと任意の1回挿入の保存をリスト帰納法で合成し、全入力列への不変条件保存を証明しています。
- 任意の値 `value` について、空状態への実装の1回挿入後に状態不変条件が成り立つことを直接証明しています。これは1要素入力 `#[value]` を処理した状態が不変条件を満たす定理の基底であり、値の列挙に依存しません。
- この不変条件と一般の中央値仕様一致定理を合成し、公開関数 `medianOf #[value]` が任意の `value` を分母1で返すことも証明しています。
- 2要素のソート基準仕様について、任意の二値と重複を許す形で中央値が二値の和／2になる一般定理があります。実装についても、2要素入力で状態不変条件と全接頭辞検査の成功を証明し、公開関数が二値の平均を返します。これらの固定長契約は、後から完成した任意長の一般証明の具体的な帰結です。
- 任意の3値について、逐次挿入後の状態不変条件と全4接頭辞でのBoolean検査成功を一般証明しています。長さ4以下の任意の不変状態への挿入保存と、挿入後の状態検査成功を証明しました。これを合成し、サイズ5以下の任意配列に対する `ofArray` の不変条件・全接頭辞の検査成功、および公開中央値と独立したソート仕様との一致も一般定理として導けます。
- 任意の入力・状態不変条件・挿入値について、1回の実装挿入が不変条件を保つ一般定理を証明しました。挿入値の根比較による振り分け、追加後ヒープ順序と境界、要素分割、サイズ差の閉区間での再平衡契約を合成しています。さらに任意の値列に対する `List.foldl` の挿入保存を帰納的に示し、`ofArray` の最終状態不変条件を任意長で導きました。
- 入力長2以下の不変状態からの挿入については、ヒープのサイズ式で長さ2の状態を1+1要素に特定し、前項の両分岐へ帰着する一般定理があります。任意値の挿入後の不変条件、状態検査器の成功、中央値仕様一致を導けます。この定理は任意の不変状態を仮定し、`ofArray` に限定しません。
- 長さ3から16までの各固定長証明は、任意ヒープ長の挿入・根移動・再平衡契約を組み立てる過程で得た一般補題です。値の分岐やサイズ別の挙動を具体的に記述するため、引き続き有用な補助契約として保持しています。現在はこれらに依存せず、任意長の状態不変条件・全接頭辞検査成功・中央値仕様一致を証明しています。

- 任意サイズの最大・最小ヒープに対する挿入後のヒープ順序保存を証明しました。末尾追加で生じる例外辺・部分木上限の初期化、1回の交換での親への移動、停止時の修復をループ不変条件にまとめ、任意回の `siftUp` 実行へ接続しています。この一般定理を任意長の状態不変条件保存へ合成しました。
- 優先関係の推移性から、ヒープ上の任意の祖先・子孫間に値の境界を伝播する補題もあります。これは経路上の比較をまとめる補助結果です。配列交換後の辺を保つ議論は別の一般交換定理で扱い、両者を反復全体へ接続する不変条件も証明済みです。

HeapSort の検証済み `popMax` と一致し、最大値を返し、残余のヒープ条件と根以外の要素保存を満たします。子方向調整の1反復は停止時に配列・添字を維持し、継続時には有効な子へ移動して要素を保存します。最後の停止反復も含む `heap.size - index + 1` を停止測度として、ループ全体の配列長保存と要素順列保存を証明しています。
- 任意の優先関数について、元ヒープと追加値が属する閉区間は、挿入後の全要素について保たれます。上界だけを仮定した場合も、挿入後に上界を超えない定理があります。
- 任意の優先関数・配列で、ヒープ検査器が「存在する子は親より優先されない」という論理条件と同値であることを示します。最小ヒープに特化した検査結果は、各子が親以上である数値仕様 `MinHeap` とも同値です。この数値仕様から任意の祖先が部分木内の全子孫以下であることを示し、その根の場合として根が全要素以下であることを導いています。`popHeap` が成功した場合には、取り出し値が最小値であり、残余が根以外の入力要素の順列で、長さが1減ることをまとめた契約も導いています。さらに、最小ヒープの根を任意の値で置換しても、根より下の親子辺は保たれる一般補題を追加しています。根を除いた末尾配列も最小ヒープの順序を保つため、この2つの結果から末尾値での根置換後に根以外の辺が保たれる定理を導いています。残る修復対象を根の部分木に限定できます。根を末尾値で置換した配列では根以外の辺が保たれることと、`siftDown` の一般定理を合成し、最小ヒープからの取り出し後も残余が最小ヒープであることを証明しています。既存の最小値・順列・長さの結果と合わせた無条件の取り出し契約もあります。優先関係が推移的なら、根が全要素以上に優先されます。

#### 不変条件から導く中央値

#### 状態検査器と派生則

- サイズ不変条件から、奇数要素では下側ヒープの根、偶数要素では両根の平均を中央値として返すこと、非空状態では中央値が存在することを導きます。根が入力に含まれることと、下側の根が上側の根以下であることも証明しています。
- 値に上下限がある場合の中央値の上下界、奇数・偶数の場合の境界値条件も示しています。
- 状態検査器は、入力要素の分割、共有 `MaxHeap` 仕様と数値 `MinHeap` 仕様、上下ヒープ間の大小関係（ヒープ順序の下で全要素間条件と根比較が同値）、サイズ差からなる条件と同値です。また、新しい値が反対側ヒープとの境界内にあれば、上下どちらへの挿入でも全要素間の境界が保たれることを順列保存から証明しています。さらに、実装の振り分け条件を使い、下側の根より大きい値を上側へ送る場合と、下側の根以下の値を下側へ送る場合の両方で境界が保たれることを示し、その2分岐の結果を1つの定理にまとめています。不変条件の下では下側が空なら上側も空となるため、空状態を含む実装分岐全体についても境界保存を1つの一般定理で示しています。振り分け直後（再平衡前）については、下側ヒープが空なら下側へ挿入し、非空なら根と比較して送り先を選ぶ実装の分岐をそのまま使い、選んだヒープのサイズが1つ増えて入力要素の分割が保たれる一般定理を示しています。また、`popHeap` の成功後に根を反対側へ挿入する抽象的な1回の移動について、移動方向の両方で2ヒープの連結要素の順列と合計サイズが保存されることを証明しています。この移動契約はヒープ順序の保存までは含みません。この独立仕様による同値定理と、汎用 `HeapOrdered` で記述した論理的不変条件との同値も証明しています。検査成功から、非空な両ヒープの根が下側から上側へ非減少であることを直接導けます。また、下側ヒープの最大値取り出し契約と、上側ヒープの最小値・残余要素・長さに関する取り出し契約も導けます。不変条件下では、任意の Boolean 条件を満たす入力要素数が二つのヒープに正確に分配され、各値の重複数も二つのヒープでの出現回数の和として保存されます。また、両ヒープを個別に整列して連結した列とその配列化が、入力のマージソート結果およびその配列化にそれぞれ一致します。従って、ヒープ根から計算する中央値はソート基準の仕様と一致します。`medianOf` に対する一般定理もあり、最終状態が不変条件を満たせば公開関数の結果が仕様と一致します。
- 入力配列を同じ要素の順列に置き換えても、不変条件と状態検査器の結果は変わりません。さらに任意の入力列の順列に対し、公開中央値の結果も一致する一般定理があります。
- 下側・上側ヒープの要素数はそれぞれ `(input.size + 1) / 2` と `input.size / 2` です。全接頭辞の検査結果から、各接頭辞で不変条件と中央値一致が成り立つことも導けます。
- ヒープ間のサイズ均衡と入力長の偶奇の同値も、不変条件から直接導いています。入力長が偶数であることと両ヒープが同数であること、奇数であることと下側が1つ多いことがそれぞれ同値です。
- 全接頭辞の Boolean 検査 `inputCheck` が成功することは、各接頭辞で状態不変条件が成り立つことと同値であり、任意入力で必ず成功することも証明しています。その不変条件から、公開関数 `medianOf` のソート基準仕様との一致を導きます。配列連結に対する状態合成則、順列入力での中央値一致、最終状態の不変条件だけを使う版も証明しています。

- 既存ヒープが順序済みなら、末尾追加後の `heapCheck` 成功は、新しい葉が親との比較で停止する条件と同値です。この結果は末尾追加だけの条件であり、一般の `siftUp` 後の順序保存を示すものではありません。

### 任意長の一般証明

#### 下降処理と根の取り出し

最大・最小ヒープの下降、根取り出し契約、順序付きヒープで根が最優先になる一般定理も証明済みです。最小ヒープでは、根以外の辺が順序付けられていれば `siftDown` が全体の順序を回復し、`popHeap` は最小値を返して残余ヒープの順序を保ちます。末尾追加で順序が保たれる条件は、新しい葉と親の比較で特徴付けられます。
