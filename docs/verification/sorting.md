# ソートの検証

[検証カタログ](../verification.md) | [English](sorting.en.md)

## 共通仕様

対象: `LeanExperiments/Verification/Sorting/Spec.lean`

`Correct input output` は、出力が昇順であり、入力の全要素を重複数も含めて保存することを表します。この仕様から、長さ・総和・各値の出現回数が保存されること、正しい非空出力の先頭と末尾がそれぞれ最小値・最大値であることを導けます。

出力が入力の順列であることを別の一般定理で示せば、共通の Boolean 検査器が昇順性だけを判定するという同値を利用できます。各ソート実装の要素保存証明と、独立仕様の照合を分離できます。

ヒープソートの配列仕様も、配列をリストへ変換してこの共通仕様を再利用します。

## Quick sort

### 一般証明

- 再帰版とループ版の両方が任意入力で共通仕様 `Correct` を満たします。
- 分割した「pivot 以下」と「pivot より大きい」列は入力の順列であり、所属条件・境界条件・互いに素であることを示しています。任意の Boolean 分類について、要素数が左右へ分配されることも証明しています。
- 再帰ソート後も各値が pivot の正しい側に残ることと、左右の出力の順序を補題として示しています。
- ループ版ではタスクスタックの意味的不変条件と停止測度を使い、VCGen で再帰版との一致を任意入力について証明しています。
- 再帰版・ループ版それぞれについて、共通 Boolean 検査器の成功が出力昇順性と同値であることを、一般の順列保存定理から導いています。

### 有限確認

ループ版について、仕様適合と再帰版との一致を次の範囲で確認し、各領域の結果を `Correct` 命題として取り出せます。

- 値0〜2、長さ0〜5の全364入力
- 値0〜3、長さ0〜8の全87,381入力
- 値0・1・2・`2³²`・`2⁶⁴−1`、長さ0〜7の全97,656入力
- 長さ63・64・65・127・128・129・255・256・257・511・512・513の整列済み・逆順などの偏り入力、および64 bit 境界値パターン
- 長さ1023・1024・1025の整列済み・逆順・全同値・周期列

## Merge sort

### 一般証明

- 再帰版とループ版が任意入力で `Correct` を満たします。
- ループ版は隣接 run の併合モデルと一致します。run 数の幾何的減少から、入力長が `2^rounds` 以下なら固定 `rounds` pass モデルとも一致します。
- 両実装の出力一致に加え、正しい昇順結果の一意性、冪等性、最小値・最大値の配置、整列済み入力を変えないことを示しています。
- 再帰版・反復版のどちらも、共通 Boolean 検査器の成功が出力昇順性と同値であることを、各実装の一般の順列保存定理から導いています。
- ループ版では出力一致と入力間の順列関係の同値、長さ・総和・任意の Boolean 条件に合う要素数の保存、順位ごとの値の上下界も証明しています。

### 有限確認

ループ版について、長さ1023・1024・1025の整列済み・逆順・全同値・周期列を確認します。ソート系全体では、長さ63〜513のヒープ階層境界付近と長さ64の代表列、さらに長さ63〜513の48個の64 bit 境界値パターンも確認します。

## Heap sort

### 一般証明

- Boolean 正当性検査器は、昇順性と入力要素の保存からなる論理仕様と同値です。同じ入力で検査を通る出力の一致も導けます。
- 最大ヒープの親子条件を論理仕様として定義し、その Boolean 検査器との同値と、根が全要素以上になることを証明しています。
- 仕様上のヒープ構築では配列長と自然数値の総和が保存されます。ループ版・再帰版の `popMax` は返却値が根に等しく、空配列の場合に限り `none` となります。

#### 抽象的な抽出契約

- 任意の抽出関数に対する残余仕様と Boolean 検査器の同値を示しています。仕様を満たす抽出関数は最大ヒープから非増加列を作り、残余を含めて入力要素を保存します。十分な fuel で抽出列を反転すれば、共通ソート仕様を満たします。
- 十分な fuel を与えた同一ヒープからの抽出列は、fuel の値によらず一致します。反転後の出力が共通ソート仕様の一意な結果であることから証明しています。
- fuel が入力サイズ以下の部分抽出列は、同じヒープから十分な fuel で得た抽出列の prefix です。途中停止した結果を完了時の結果と比較できます。
- 残余契約を満たす二つの抽出実装は、同じ最大ヒープから同じ fuel で抽出する場合、部分列も一致します。完了列の一意性と prefix 定理を合成しています。
- 抽出契約がサイズ上限内でしか成立しない場合も、その範囲で完了した二つの抽出実装のソート結果は一致します。有限範囲で証明した抽出実装を比較するための合成定理です。
- ヒープ構築の正しさとサイズ上限付きの抽出契約を合成し、上限内の入力に対するソート仕様を導けます。
- サイズ上限付きの抽出契約でも、部分抽出列は完了列の prefix となり、同じヒープ上の二実装は途中結果まで一致します。サイズ9以下の再帰版 `popMax` のような有界証明を、段階ごとの動作比較に使えます。
- サイズ上限付き契約から、fuel がヒープ長以下の途中抽出列も降順であると証明できます。完了抽出列の降順性と prefix 定理を合成する一般定理です。
- 同じ範囲では、抽出済み要素数が fuel と一致します。有界契約のもとで抽出が途中停止しないことを示します。
- 有界契約による部分抽出列を反転すると、共通の `Ascending` 仕様を満たします。途中までの最大値抽出結果をソート済みの top-k 列として扱えます。

#### 部分実行と再開

- 抽象抽出列と `drainRecursive` の一致を使い、実行関数の途中結果も昇順かつ要素数が fuel と一致すると導けます。
- 降順の既存出力から途中再開する場合も、残余ヒープが既存値以下なら結果は昇順となり、配列長は既存出力長に fuel を足した値になります。
- `drainRecursive` の途中出力と残余ヒープを合わせると、任意の Boolean 条件に合う要素数が入力と一致します。停止後の出力配列と未処理ヒープについて直接述べた分割不変条件です。
- 既存の蓄積出力から再開する場合も、再開前の出力とヒープの分類個数は、再開後の出力と残余ヒープに分配されます。既存出力の順序を仮定せず、途中再開の要素保存を確認できます。
- サイズ上限付き抽出契約では、部分再開の昇順性・追加要素数・任意分類の保存を一つの一般契約として取り出せます。出力順序の条件と要素保存の条件を同じ前提から確認できます。

#### サイズ上限付きの補助結果

- 入力長9以下で再帰版ヒープ構築の結果が最大ヒープなら、任意の自然数値についてソート正当性を導けます。構築後のヒープ条件を証明すれば、既存の長さ9以下の抽出契約と一般の要素保存から全体の正当性が従います。
- 長さ9で入力の根が最大値なら、左右部分木のヒープ化と根の不変性を合成し、再帰版ヒープソート全体の正当性を証明しています。値を限定しない定理ですが、根が最大値であるという前提付きです。
- この条件を長さ9以下の統一した定理にもまとめています。長さ8以下では任意入力を扱い、追加の根最大条件が必要なのは長さ9だけです。
- 長さ9では前提をさらに弱め、添字3・2・1を処理した後に根がその子以上であることだけから、構築およびソート全体の正当性を導けます。これは根最大条件を必要とせず、最後の下降段階に残る条件を直接表します。
- この弱い条件による結果も長さ9以下の統一定理にまとめています。長さ8以下は無条件で、根段階の条件が必要なのは長さ9だけです。

#### 部分排出の性質

- 実際の途中出力値は、完了時に後から取り出される値以上です。有界な抽出契約における top-k 性質を再帰版排出へ移しています。
- 最大ヒープ入力とサイズ上限付きの抽出契約から、`drainRecursive` の完了出力が昇順で入力の順列になることを導けます。
- 排出の再開にも一般化し、既存出力が降順かつ残余ヒープの全要素以上なら、再開後も連結した要素列が正しくソートされます。
- 任意の抽出関数について、fuel を二段に分けた抽出列は各段の列の連結と一致し、最終残余も一括実行と一致します。抽出仕様に依存しない分割実行の合成則です。
- `drainRecursive` 自体も、第一段の抽出列を蓄積出力に戻し、残余ヒープから続行すれば一括実行と同じ結果になります。
- サイズ上限付き契約でも、部分抽出列と残余ヒープを合わせた要素は入力の順列です。任意の Boolean 条件に一致する値の個数も、両者の合計で保存されます。
- 途中抽出列の各値は、完了列で後に現れる未抽出値以上です。有界な抽出契約に対して、上位 `fuel` 個を途中結果が選んでいることを一般に示します。
- 要素保存だけを仮定する抽出関数では、任意 fuel の途中状態でも、抽出済み列と残余配列を合わせた任意の Boolean 条件の要素数が入力と一致します。抽出順序やヒープ条件に依存しない一般的な分割不変条件です。
- 残余仕様を満たす抽出関数では、任意 fuel 後の残余配列長が `入力長 - fuel`（0未満は0）と一致します。抽出回数と残余長の境界を正確に示す停止・fuel の定理です。
- 同じ契約から、抽出済み要素数は `min fuel 入力長` と示せます。fuel が十分なら全要素をちょうど一度ずつ処理し、不足時は fuel 回だけ処理します。
- より弱い要素保存・サイズ減少契約だけでも、任意 fuel 後の残余長が `入力長 - fuel`、抽出数が `min fuel 入力長` と示せます。ヒープ条件や抽出順序を使わない停止進捗の性質です。

#### 任意長の再帰版実装

- 再帰版ヒープ構築は、任意の入力から最大ヒープを作り、要素を順列として保存します。未処理添字以上の親子辺がヒープ条件を満たす不変条件を使い、各下降後に処理範囲を根へ広げています。構築結果は独立した Boolean 検査器にも必ず合格します。
- 任意サイズの最大ヒープから再帰版 `popMax` を行うと、根の抽出・残余の最大ヒープ性・残余要素の保存を満たします。これらを抽象抽出契約と合成した一般定理により、再帰版 `heapSortRecursive` は任意長・任意の自然数値の入力を `Correct` にソートし、その出力は独立 Boolean 検査器にも合格します。
- 長さ9以下の最大ヒープ入力では、再帰版構築が入力を保つ性質と最大ヒープ向けの抽出契約を合成し、`heapSortRecursive` が正しくソートすることを証明しています。
- 再帰版 `heapSortRecursive` は任意長で入力要素を順列として保存し、配列長と自然数値の総和も保ちます。この一般定理は出力の整列性とは別の性質です。
- 任意長の再帰版ソート正当性は、出力の昇順性と同値です。要素保存の一般証明と出力昇順性の一般証明を組み合わせ、無制限の `Correct` 定理を得ています。独立した Boolean 検査器も任意入力で昇順性を正確に判定します。
- 再帰版の排出処理は、任意の fuel・ヒープ・既存出力について、抽象的な最大値抽出列を既存出力に連結して反転した結果と一致します。抽出列の一般仕様と実装の接続を示す定理です。

#### ループ版との対応

- 命令的な `siftDown` は、任意の配列・根位置で再帰版 `siftDownRecursive` と一致します。1段の状態遷移、不変条件の保存、停止時の固定点性、停止測度を合成した一般証明です。この一致から、再帰版下降について証明した一般契約をループ版にも移せます。
- ループ版ヒープ構築は、残りの再帰構築結果を保つループ不変条件と下降処理の一致定理により、再帰版と任意入力で一致します。したがって任意入力で最大ヒープ条件と入力要素の順列保存を満たし、独立した Boolean 検査器にも合格します。
- ループ版 `popMax` は任意の配列で再帰版と一致し、配列サイズと要素保存の一般契約を満たします。抽出値と残余を合わせた任意分類の個数保存も、両実装について直接証明しています。さらに、ループ版の結果についても、最大ヒープ入力なら残余が最大ヒープであり、根を除いた要素の順列であることを直接取り出せます。残余仕様の Boolean 検査器にも合格します。
- 最大ヒープからの再帰版・ループ版 `popMax` は、空なら失敗し、成功時は根を返し、全入力要素が返却値以下で、残余配列が残余要素を順列として保存する最大値順序仕様を満たします。
- ループ版 `heapSort` は、残り回数と再帰排出の結果を結ぶ不変条件により、任意入力で再帰版 `heapSortRecursive` と一致します。従ってループ版自身も任意長・任意値の `Correct` を満たし、独立 Boolean 検査器に合格します。
- 再帰版・ループ版それぞれで、任意の候補出力が実装結果と一致すること、共通仕様 `Correct` を満たすこと、独立 Boolean 検査器に合格することが同値です。正当な候補を与えれば実装結果そのものだと結論できます。
- ループ版 `heapSort` は、任意長・任意値で配列長、自然数値の総和、任意の Boolean 条件に合う要素数を保ちます。特に個数定理は重複値の保存を含む要素保存契約を直接表します。

#### 共通仕様から導く性質

- ソート共通仕様では、非減少関数による写像が `Correct` を保つことを一般証明しています。その系として、任意の単調変換 `f` に対し、ループ版・再帰版それぞれで `heapSort (input.map f) = (heapSort input).map f` に相当する可換性が成り立ちます。
- 共通仕様から、正しいソート関数と非減少写像が可換である一般定理も導いています。HeapSort・MergeSort・QuickSortの再帰版と命令版に適用しています。
- 共通仕様を満たす任意のリストソート関数について、順列関係にある入力は同じ出力になり、昇順入力は変更されず、ソートを繰り返しても結果が変わりません。3種類のソートの再帰版・命令版に適用しています。HeapSortでは配列をリスト共通仕様へ接続します。
- 配列版HeapSortでは、ループ版・再帰版のどちらも「入力をそのまま返す」ことと「入力が昇順である」ことが同値です。任意長・重複値を含む入力に対する必要十分条件です。
- 配列版HeapSortの共通仕様でも、二つの出力が一致することと入力配列をリスト化した列が順列であることの同値を証明しています。ループ版同士・再帰版同士に加え、実装版が異なる場合にも、任意の二入力について出力一致を特徴付けます。
- 任意の Boolean 条件による絞り込みは、HeapSort・QuickSortの両実装と可換です。配列版HeapSortはリスト共通仕様へ接続し、QuickSortとともに共通定理 `Correct.sort_filter` を使っています。
- 同じ `Correct.sort_filter` を再帰版・命令版MergeSortにも適用し、ループ方式によらずソート正当性から結論を導いています。
- `Correct` を満たす任意のソート関数では、連結入力の結果が左右の部分ソート結果を `merge` した結果に一致します。この一般則をMergeSort・QuickSortの再帰版と命令版、およびHeapSortの配列版へ適用しています。
- 共通の `Correct` を満たす任意のリストソート関数について、チャンク連結後のソート結果は、各チャンクを同じ関数でソートして右から `merge` した結果に一致します。この一般定理を再帰版・命令版MergeSortに個別に適用しています。
- 同じ共通仕様から、チャンクの順序を入れ替えても、連結後のソート結果と右畳み込みによる併合結果が変わらないことを示します。任意のチャンク順列に対する一般定理で、実装内部の順序や併合手順に依存しません。
- 全葉が昇順runである任意の二分併合木について、葉の連結が同じrun列と順列関係なら、評価結果は右畳み込みによる併合結果と一致します。併合木の形を任意に変えても結果が保たれる一般定理です。
- 任意の昇順run併合木の評価は、同じ入力または順列関係にある入力を `Correct` にソートする任意の実装結果とも一致します。木の併合順とソート実装を共通仕様の一意性で直接結びます。
- 配列を連結してからループ版または再帰版HeapSortする結果は、左右を個別に同じ実装でHeapSortしてからマージソートの `merge` で併合する結果と任意入力で一致します。各段階の正当性と共通仕様の一意性による一般的な分割・併合則です。
- 再帰版・ループ版それぞれのヒープソート結果は、独立なマージソートの結果配列と任意入力で一致します。共通のソート仕様を満たす出力の一意性を使い、別実装との直接比較を一般定理にしています。
- MergeSort・QuickSort・HeapSort の再帰版と反復版は、各出力位置の値を入力中でそれより小さい要素数・以下の要素数から特徴付けます。重複値を含む任意入力でも、値が占める順位範囲を正確に得られます。
- 再帰版・ループ版HeapSortでは、先頭 `k` 個に含まれる `<`・`≤`・`>`・`≥` の各値の個数を、入力全体の個数から任意長・任意しきい値で求められます。共通仕様のtop-k定理を配列実装の公開補題にも接続しています。
- MergeSort・QuickSortの再帰版と反復版にも、`≤`・`>`・`≥` の先頭個数定理を実装固有の公開補題として接続しました。既存の `<` 定理と合わせ、全ソート実装のtop-k個数保証を揃えています。
- 任意のしきい値について、出力先頭 `k` 個に含まれるしきい値未満の要素数は、`k` と入力中のその要素数の小さい方に一致します。重複を含め、先頭部分が入力の最小側から正確に選ばれていることを top-k の形で示します。
- 共通 `Correct` 仕様を満たす任意のソート結果でも、先頭 `k` 個にあるしきい値以下の要素数が `k` と入力全体での個数の小さい方に一致します。しきい値と等しい重複値も含めた境界個数を特徴付けます。
- 同じ先頭部分にあるしきい値より大きい値の個数は、入力中の該当個数と、しきい値以下の値を数えた後に残る `k` 枠の小さい方に一致します。小さい側・大きい側の両方から境界を特徴付けます。
- しきい値以上の値についても同じ個数公式が成り立ち、しきい値0の境界を含めて自然数全域で適用できます。
- 先頭 `k` 個を除いた suffix に残るしきい値以下の要素数は、入力全体の個数から先頭で数えた個数を引いた値です。`take` と `drop` に分割した後も重複数が保たれます。
- suffix に残るしきい値超過値の個数も、入力全体の個数から prefix で選ばれた分を引いて正確に求められます。小さい値と大きい値の残数をそれぞれ一般式で表します。
- suffix に残るしきい値以上の個数も同様に特徴付けられます。しきい値0では全要素が該当する境界を含め、prefix/suffix の両側で `<`・`≤`・`>`・`≥` の個数を扱えます。
- 任意のBoolean述語についても、suffix内の該当数は入力全体の該当数からprefix内の該当数を引いた値です。この分割則自体はソート順に依存せず、共通仕様の要素保存から導きます。
- 同じ一般則を加法形でも示し、prefixとsuffixの個数の和が入力全体の個数に一致することを証明しています。減算の境界処理を使わず、任意分類の分割を直接表す定理です。
- 出力が全要素間で狭義昇順になることと、入力に重複値がないことは同値です。入力の重複の有無を、ソート後の値の並びから判定できます。
- 非空入力では、両実装の出力先頭が入力中の最小値、末尾が最大値であることを示します。要素の所属と全入力値に対する境界も含む一般定理です。
- 共通の `Correct` 仕様の一意性から、両実装の出力が入力順序によらず要素の多重集合だけで決まり、出力を再度ソートしても変わらないことを任意入力について導いています。

#### 下降処理とヒープ木の補題

- fuel 付き下降処理は任意の fuel・入力・根位置で配列長と要素の順列関係を保存します。さらに、再帰先より前の添字を変えないフレーム定理から、任意 fuel の結果が入力リストの prefix を保つことと、開始位置以降の suffix 内で要素を順列として保存することを導いています。この suffix の長さ・自然数値の総和・任意の Boolean 条件に合う要素数も保存されます。正の fuel では、処理後の根の値が開始時に選ばれた最大候補と一致し、その左右の子を支配します。再帰版にも同じ支配性が成立します。下降結果が入力と等しい条件は、fuel が0か根が存在する子を支配することと同値です。正の fuel では、根の値が下降後に厳密に増えることと、開始時に根より大きい子が存在することが同値で、根添字が配列外の場合も含みます。fuel は `values.size - root` まで短縮でき、再帰版の結果もこの必要段数の fuel で得られる一般定理を示しています。
- 再帰版 `siftDownRecursive` は任意の配列・根位置で配列長と要素の順列関係を保ち、左の子が配列外なら配列を変更しません。長さ5・6・7・8の根からの下降結果と、長さ6・7・8の子位置からの下降結果を比較による場合分けで一般式にし、長さ8では添字1・2・3で下降後の部分木条件も証明しています。長さ9でも添字1・2・3の下降結果と各部分木条件を導き、構築ループで添字3・2・1を処理した後に左右部分木がヒープになることを示しています。`popMaxRecursive` は成功時に残余配列の長さをちょうど1減らし、入力の根以外の要素を順列として保存します。一般の抽出要素保存仕様から、取り出した値と残余列を合わせた任意条件の要素数保存も導けます。
- 一般の根位置で、入力のうち根より大きい親添字の親子条件が成立していれば、再帰版下降後の根が出力部分木全体を支配します。さらに、選択した子部分木の外側にある親子辺は下降前後で同値です。根辺の回復と、再帰先が触れない辺の保存を分離した一般補題です。
- 任意の根位置で、その根より下の親子辺がすでに最大ヒープなら、十分な fuel の下降処理後に根の部分木全体が最大ヒープになることを証明しています。これを使い、根以外の親子辺を保つ再帰版 `siftDown` が任意の最大ヒープを最大ヒープのままにし、再帰版 `popMax` の残余も任意サイズで最大ヒープになることを導いています。
- HeapDescendant では、根より後ろの子孫が根の左右どちらの子を通るかを取り出せます。また、左右の異なる子の部分木が交わらないことを任意の深さで証明しています。これらの添字木の構造補題は、配列ヒープ上の部分木不変条件を分割する共通基盤です。

### 有限確認

- 両ヒープ構築版のヒープ条件と要素保存を、基本121入力、値0〜3の長さ0〜8の全87,381入力、64 bit 値を含む長さ0〜7の全97,656入力、および長さ63〜513の48境界値入力で確認します。
- 両 `siftDown` 版について、これらの領域で根位置ごとの出力一致と要素保存を確認します。両構築版と両抽出版の4通りの組合せでも残余仕様を検査します。
- 両ソート実装について、長さ64・63〜513の境界列、64 bit 境界値入力、さらに長さ1023・1024・1025の代表列で仕様適合と実装間一致を確認します。
